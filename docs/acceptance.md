## 上线前仍需完成

1. 按 `docs/deployment.md` 切换生产启动入口并安装插件，先保持 observe；这会涉及 Paseo 服务切换，尚未执行。
2. 在手机实际打开“额度保护”，验收布局、用量刷新、账户选择以及通知点击后的目的页面。当前不承诺通知栏原生“一键暂停”。
3. 使用专门的真实 Claude/Codex 测试会话，验收手动暂停、原会话手动继续及子任务停止状态；当前中断测试主要使用 provider 测试替身，不能代替此项。
4. 对正式接入的执行层验证受控阈值触发和失联保护，不故意将真实订阅消耗到阈值；检查部分停止失败的显示及通知。
5. 完成这些验收后启用 enforce 和开机后台服务，再观察持续运行、额度重置与通知重试。

暂停通过中断当前轮次和阻止后续请求实现，不默认杀掉 Claude/Codex 进程。恢复只解除账户限制，用户在原会话继续；不会自动重放旧任务。采样和在途请求存在延迟，阈值不是计费硬上限。

## 恢复与通知回归

`npm test` 包含 `test/recovery-notifications.test.mjs`：使用内存/临时 SQLite、隔离 Unix socket 和推送替身，不调用模型或真实手机推送。

- 限流与超时的有效缓存可恢复；过期、账户缺失、登录失效、无效窗口、最新超限不能恢复；覆盖自定义阈值和 Codex 单窗口。
- 回放跨秒及跨时区的重置时间抖动，验证同周期只预警一次；覆盖真实换周期、双窗口合并、未知重置时间、保存设置、开关切换和重启。
- 旧状态迁移保留预警周期和暂停状态、取消重复积压；不伪造手机送达。
- 回放截图中的 24 秒暂停过程，仅一次完成通知；持续未停止满 60 秒才异常提醒，明确失败即时提醒，跨重启计时和去重。
- 新读数满足全部受控窗口恢复线后自动解除额度保护暂停并通知；手动暂停、缺失/过期/错误数据不会误恢复。覆盖自定义阈值、Codex 单窗口、恢复到预警区间合并提醒、关闭通知仍恢复、推送失败重试、重新暂停撤销旧恢复通知与旧库迁移。
- 失败退避重试，过时通知取消，零关联任务和未确认结果不夸大执行范围。

## 逐卡 Reset 回归

本地修改支持用户自行决定重置时机：每张有效卡独立显示 Reset，确认后提交指定卡片；不再要求额度触顶。`npm test` 覆盖指定第二/第三张卡、账户匹配、过期或失效卡不替换、接口各类结果、超时后的查询、重启/跨客户端重试幂等、并发限制及刷新失败保留已确认结果。

`npm test --prefix plugin` 使用实际组件和最小宿主适配验证逐卡按钮、选择后重排、所选卡消失/过期、提交期间禁用。这是组件交互测试，不代替真实手机布局验收。测试只使用 Codex app-server 和推送替身，不调用模型、不消耗真实重置卡；本次未更新生产。
